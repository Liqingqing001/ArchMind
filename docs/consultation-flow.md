# 顾问对话与场景检索

## 需求先于方案

对话按 collecting → ready → generated 推进。每轮最多追问两个尚未回答的关键条件：目标、预算及周期、使用方式、操作经验、产出规模和质量／隐私等要求。明确说“不确定”也是有效回答，方案需注明假设。

真实 API 使用一次结构化需求提取调用，只接受带用户原文引文的字段更新；格式错误、没有对应引文、输出截断都报错，不保存错误摘要或降级成模拟回复。程序生成追问和确认摘要，模型不能绕过确认提前输出方案。需求齐备后仍需用户点击确认按钮或回复明确确认；条件修改后再次确认。首次把全部条件写齐，也先返回摘要。

摘要存于会话最近一次助手回复的 result.workflow；不需要数据库迁移。后续检索使用独立摘要，聊天历史缩短不再丢掉目标和预算。旧会话在首次发送时从既有用户陈述提取摘要，并重新确认；保留原有消息。更换目标场景时重问规模和关键要求。

## 简洁输出和截断

方案默认要求约 450～800 字，先给主推，再按适用性比较至多三条路线，解释使用方向、适合原因、费用和链接；后续问答默认约 250～450 字，具体追问可更短。字数为模型指令，不通过裁切正文强行执行。默认模型输出预算仍为 2400 tokens，可在连接设置调整；不是 2400 字，部分推理模型会在预算中计入推理。

达到输出上限时保留完整已收到正文，标记不完整，并提供显式续写和调整预算入口，不自动重试或额外付费调用。续写只在最后回复确实因长度停止时允许，沿用原来的证据版本、引用编号及 trace，不用新资料改写旧引用。记录安全的停止原因、上限和服务商返回的 token 数量；不保存原始服务商响应或密钥。内容过滤与长度停止分别提示。网络/CORS 和 75 秒超时仍明确报错。

## 检索与场景知识

backend/data/solution-policy.json 是 Python 和 TypeScript 的共享规则：流程提示、字段问题、确认词、场景任务、路线指南、分词扩展和停用词。两端使用相同排名算法，测试共用 backend/tests/fixtures/solution-parity.json。

检索读取各自当前已发布事实，不另建 Agent 私库。以确认后的完整目标和关键要求检索，排除演示和厂商组织简介；按任务分配证据，每个实体最多两条、总计十二条，补充资料保留原文、版本与来源。现成平台路线排除工作流、算力及仅下载权重的条目；算力仅在用户明确选择本地／GPU／自部署时进入候选。已标记 Legacy 或停止服务的实体默认不用于推荐。当前仍是场景约束的关键词检索，不宣称实现向量检索或准确报价；可选联网检索详见 [联网检索](web-search.md)。

视频短剧路线分为现成平台、API 与工作流、云 GPU 自部署。知识页显示各自适用条件、任务链和缺口。指南是编辑建议，尚未通过真实作品跑通和计费验证；不能作为产品事实引用，也不能保证角色一致性、硬件规格或预算。价格、商用、地域库存及具体节点版本仍需核验。

## 新增 ComfyUI 资料

公开数据新增 ComfyUI 的四条官方 README 摘录事实，Pages 构建自动包含；已有访客数据追加合并，保留聊天、审核和 API 配置。完整后端数据库由用户显式导入，SQLite 与 PostgreSQL 都支持：

```bash
cd backend
# 先完成现有 alembic upgrade head
python -m app.curated --dataset video-workflow-knowledge-2026-11-07.json          # 预览，事务回滚
python -m app.curated --dataset video-workflow-knowledge-2026-11-07.json --apply  # 导入 ComfyUI 短摘录
```

已有事实不同值进入待审核，不覆盖已发布值；重复导入不新增同一事实或待审核变更。未自动变更服务器数据库。README 的 MiniMax H3 支持列举不证明权重开放、本地部署许可或某个节点在用户环境可用。

## 验收

输入视频短剧意向 → 补预算／使用方式 → 补经验／规模与关键要求 → 摘要确认 → 简版方案 → 修改预算重新确认。另测超过四轮仍保留最初目标、刷新恢复、会话隔离、模型错误不降级、截断续写证据固定及手机布局。模型端交互验收使用受控响应，不代表所有供应商的真实生成效果已验证。

当前面向新手的回答约 450～800 字，按适用性排序解释至多三条路线与链接。完成后的评价和场景参考见 [方案沉淀](solution-cases.md)。

## “没有偏好”澄清修复（2026-11-08）

使用方式仍待回答时，独立的“没有偏好／无偏好”回答会由两端共享规则补记，即使模型漏提取也继续询问后续条件。带序号的回答只匹配对应问题；反问、引述、画风偏好不补记为部署偏好。模型提取到的明确选择优先。静态演示不再把一句“不知道”同时填进两个字段，也不把“比较三条路线”直接当成选择 API。收集完成仍需用户确认生成。

MiniMax-H3 补充资料来自[官方模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3)和[许可问答](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/QA-about-License.md)。它继续归属视频生成能力，以“开放权重”标注；本地路线检索携带许可地域与组件部署边界。未验证实际硬件、显存、速度或费用。完整后端已有库可预览后导入：

```bash
cd backend
python -m app.curated --dataset minimax-h3-open-weights-2026-11-08.json
python -m app.curated --dataset minimax-h3-open-weights-2026-11-08.json --apply
```

Pages 自动追加五条事实到同一实体，保留旧来源、历史版本与浏览器记录。公开资料现有 171 个真实实体、470 条事实、21 个可下载模型。增补数据必须显式标记 `supplement`，构建器拒绝同名新实体或覆盖已有字段。
