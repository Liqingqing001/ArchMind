# 顾问对话与场景检索

## 先给候选，再逐步细化（2026-11-15）

只要已有明确目标，就直接进入检索和回答，不要求先填满六项条件，也不再额外确认生成。没有目标时仅询问目标。六类字段继续记录用户明确说过的条件，缺失项保留为未知，不把云端 API 等临时假设写成用户偏好。

- discovery：寻找/比较模型、能力、价格等。首轮直接比较2～3个有证据的候选，说明类型、适用性、限制和官方链接；最多追问1个真正影响选择的问题。
- solution：系统设计或正式方案。按已知条件给初稿，说明组合、数据流、成本项、风险和最小验证；未知条件明确标记。
- explanation：解释上一轮、不涉及新选型或价格的追问。30分钟内可复用同一会话的网页与库内证据，保留原引用和检索日期；条件改变、时效问题、正式方案或证据过期均重新检索。

真实 API 仍先调用一次结构化需求提取，只接受带用户原文的字段更新；无效 JSON、伪造引文、截断均报错，不静默降级。第二次调用根据实际证据回答。模式和缺失项通过 ANSWER_CONTEXT 传给模型；回答长度、候选数量和追问数量是模型指令，并非逐句强制校验，实际质量仍取决于模型和证据。

摘要保留在 result.workflow（version=1），增加可选 response_mode，不需要数据库迁移。旧 collecting/ready 对话在下次发送时自动按新流程继续，原消息不改写；旧确认按钮仍兼容。多会话、手动标题、并发版本校验和密钥隔离保持有效。

Pages 未连接模型时明确显示“知识库预览”，直接列库内候选及引用，不声称已经联网或完成生成。连接模型但搜索关闭时提示未核验最新信息，顶部提供搜索配置入口。模型与搜索使用各自独立的 Key。

## 简洁输出和截断

选型比较默认约 250～450 字，正式方案默认约 450～800 字，先给主推，再按适用性比较至多三条路线，解释使用方向、适合原因、费用和链接；后续问答默认约 250～450 字，具体追问可更短。字数为模型指令，不通过裁切正文强行执行。默认模型输出预算仍为 2400 tokens，可在连接设置调整；不是 2400 字，部分推理模型会在预算中计入推理。

达到输出上限时保留完整已收到正文，标记不完整，并提供显式续写和调整预算入口，不自动重试或额外付费调用。续写只在最后回复确实因长度停止时允许，沿用原来的证据版本、引用编号及 trace，不用新资料改写旧引用。记录安全的停止原因、上限和服务商返回的 token 数量；不保存原始服务商响应或密钥。内容过滤与长度停止分别提示。网络/CORS 和 75 秒超时仍明确报错。

## 检索与场景知识

backend/data/solution-policy.json 是 Python 和 TypeScript 的共享规则：流程提示、字段问题、确认词、场景任务、路线指南、分词扩展和停用词。两端使用相同排名算法，测试共用 backend/tests/fixtures/solution-parity.json。

检索读取各自当前已发布事实，不另建 Agent 私库。以已知目标和关键要求检索，排除演示和厂商组织简介；按任务分配证据，普通实体最多两条，MaaS 条目最多四条，总计十二条，补充资料保留原文、版本与来源。现成平台路线排除工作流、算力及仅下载权重的条目；算力仅在用户明确选择本地／GPU／自部署时进入候选。已标记 Legacy 或停止服务的实体默认不用于推荐。当前仍是场景约束的关键词检索，不宣称实现向量检索或准确报价；官网检索与启用条件详见 [联网检索](web-search.md)。

视频短剧路线分为现成平台、API 与工作流、云 GPU 自部署。知识页显示各自适用条件、任务链和缺口。指南是编辑建议，尚未通过真实作品跑通和计费验证；不能作为产品事实引用，也不能保证角色一致性、硬件规格或预算。价格、商用、地域库存及具体节点版本仍需核验。

## 新增 ComfyUI 资料

公开数据新增 ComfyUI 的四条官方 README 摘录事实，Pages 构建自动包含；已有访客数据追加合并，保留聊天、审核和 API 配置。完整后端数据库由用户显式导入，SQLite 与 PostgreSQL 都支持：

```powershell
cd backend
# 先完成现有 alembic upgrade head
py -m app.curated --dataset video-workflow-knowledge-2026-11-07.json          # 预览，事务回滚
py -m app.curated --dataset video-workflow-knowledge-2026-11-07.json --apply  # 导入 ComfyUI 短摘录
```

已有事实不同值进入待审核，不覆盖已发布值；重复导入不新增同一事实或待审核变更。未自动变更服务器数据库。README 的 MiniMax H3 支持列举不证明权重开放、本地部署许可或某个节点在用户环境可用。

## 验收

输入“找一个实时语音交互的模型” → 首轮知识与官网检索 → 带引用候选 → 解释追问复用近期证据 → 修改预算重新检索 → 根据已有条件生成方案。另测超过四轮仍保留最初目标、刷新恢复、会话隔离、模型错误不降级、截断续写证据固定及手机布局。模型端交互验收使用受控响应，不代表所有供应商的真实生成效果已验证。

当前面向新手的回答约 450～800 字，按适用性排序解释至多三条路线与链接。完成后的评价和场景参考见 [方案沉淀](solution-cases.md)。

## “没有偏好”澄清修复（2026-11-08）

使用方式仍待回答时，独立的“没有偏好／无偏好”回答会由两端共享规则补记，即使模型漏提取也继续询问后续条件。带序号的回答只匹配对应问题；反问、引述、画风偏好不补记为部署偏好。模型提取到的明确选择优先。静态演示不再把一句“不知道”同时填进两个字段，也不把“比较三条路线”直接当成选择 API。上述是旧版字段补记规则；新版不再等待收集完成或确认生成。

MiniMax-H3 补充资料来自[官方模型卡](https://huggingface.co/MiniMaxAI/MiniMax-H3)和[许可问答](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/QA-about-License.md)。它继续归属视频生成能力，以“开放权重”标注；本地路线检索携带许可地域与组件部署边界。未验证实际硬件、显存、速度或费用。完整后端已有库可预览后导入：

```powershell
cd backend
py -m app.curated --dataset minimax-h3-open-weights-2026-11-08.json
py -m app.curated --dataset minimax-h3-open-weights-2026-11-08.json --apply
```

Pages 自动追加五条事实到同一实体，保留旧来源、历史版本与浏览器记录。公开资料现有 171 个真实实体、470 条事实、21 个可下载模型。增补数据必须显式标记 `supplement`，构建器拒绝同名新实体或覆盖已有字段。
