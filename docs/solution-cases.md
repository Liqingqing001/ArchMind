# 评价与场景方案库

方案完整结束后，界面询问“你觉得这个方案怎么样？”，提供“挺好的、还可以、拉完了”。前两档自动保存需求摘要、完整回答、引用摘录、事实版本／快照、网页链接与检索时间；按小说写作、视频、图片、音频、知识问答、建站、模型部署等场景归档。再次评价更新同一条记录，不重复保存；改成“拉完了”后不再展示或用于参考。

入口是“知识库 → 按场景查看 → 已沉淀方案”。可按场景筛选、展开方案、查看原始依据。只有完成的助手方案可评价，需求澄清、用户消息和被截断的半成品不可入库。显式续写完成后，将同一检索记录的连续片段一起保存。保存后的方案不会随对话改名、删对话或事实版本更新而静默改写。

这是用户认可的历史参考，标记“未经实测”；不会直接变成模型能力、价格等已审核事实。同场景的新对话最多参考两份非演示、正面评价方案，排除当前对话自己的方案；上下文和检索追踪中明确记录 `saved_solution_cases`，回答下方可查看。旧报价、旧链接和适用条件仍要结合本轮库内和网页依据重新核验，不能把历史引用号冒充本轮证据。

## 保存范围

- Pages：保存到当前浏览器已有状态中，保留 API 设置与会话隔离；既不上传用户聊天，也不写入公开静态资料。重置演示会清除当前浏览器的方案和对话。静态演示方案可回看，但不进入真实模型的参考方案检索。
- 完整后端：保存到 PostgreSQL／SQLite 的 `solution_cases` 表，沿用当前工作空间的访问控制。升级后运行 `alembic upgrade head`，新增迁移 `f253dc002315`；提供 downgrade。当前仍为个人工作空间，尚未引入多人租户隔离。

## API

- `POST /api/conversations/{conversation_id}/messages/{message_id}/feedback`，仅接受 `rating: good | okay | bad`。方案从已保存消息读取，不接受客户端自造正文和引用。
- `GET /api/solution-cases?scene_id=novel`，只返回正面评价方案；不指定场景则返回当前工作空间最新 200 条。
- 读取对话时返回 `feedback` 映射，评价不会改动会话消息 revision 或覆盖并发生成。

前后端测试覆盖幂等、三档转换、证据冻结、半成品及伪造输入拒绝、删除后的行为、历史保存与参考检索。页面验收覆盖手机及桌面的评价、刷新恢复、场景浏览和引用链接。
