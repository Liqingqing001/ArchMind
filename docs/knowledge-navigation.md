# 分层知识目录

知识浏览默认提供“按场景查看”：AI 视频短剧、企业知识问答。场景页展示适用条件、生产路线、知识缺口和关联实体，标明是编辑指南而非实测案例；没有复制事实。

切换“按能力浏览”后采用“能力 → 类型 → 厂家 → 模型”的层级。全部知识首页只显示五个分组，不直接铺开全部实体。同厂家在同一类型下只出现一个入口，例如：生成类 → 大语言模型 → 阿里云 → Qwen3-8B。

```text
全部知识
├─ 生成类
│  ├─ 大语言模型 → 厂家 → 模型
│  ├─ 图片模型 → 厂家 → 模型
│  ├─ 声音模型 → 厂家 → 模型
│  └─ 视频模型 → 厂家 → 模型
├─ 理解类
│  ├─ 理解文字 → 厂家 → 模型
│  ├─ 理解图片 → 厂家 → 模型
│  ├─ 理解声音 → 厂家 → 模型
│  └─ 理解视频 → 厂家 → 模型
├─ 检索与表征 → 文本嵌入 / 重排序
├─ 工具与平台 → 应用与产品 / 技术框架 / 开源项目 / 云服务与API
└─ 其他知识 → 厂商与组织 / 行业方案 / 演示条目 / 待整理模型
```

实际子项以已登记资料为准。理解视频入口当前保留为空，不因模型被标记为多模态就推断其具备视频理解能力。待核验厂家会显式显示“厂家待核验”；演示条目单独放置。

侧栏初始折叠，可以逐层展开或全部折叠；内容区通过分组卡片逐层进入，并提供路径导航和返回上一级。搜索在当前分支内进行，结果仍按厂家分组。手机使用相同的卡片与路径，无需展开冗长分类下拉框。

## 同一知识库与来源

目录是原有实体的导航视图，不复制资料。多模态模型可同时出现在生成与理解分支，引用的是同一实体 ID、已发布事实、来源与版本；Agent 继续检索这些相同的已发布事实。保留原有数据库分类元数据与筛选接口，后台录入、审核和下载资料入口继续使用原有流程。此更新不需要新增数据库迁移。

服务端通过受保护的 `GET /api/knowledge/navigation` 提供节点、路径与实体 ID；Pages 适配器使用同样规则生成导航。需要限定 Agent 检索范围时，可使用节点返回的 `entity_ids`，导航节点 ID 不是数据库分类 ID。

## 维护规则

共享配置位于 `backend/data/navigation-policy.json`：根目录、能力映射、厂家别名与已核对的模型厂家。Python 与 TypeScript 实现均读取它，Docker 镜像也包含该文件。

- 新模型沿用多对多分类；能力规则基于已登记分类，不从名称猜测视频理解等能力。
- 同厂家别名在配置中归一化，例如 Qwen 归入阿里云；优先使用实体与厂商的显式关系。
- 嵌入与重排序模型单独归类，避免仅因附有视觉标签就被当成通用图像理解模型。
- 开放权重为资料标签，官方权重、许可证与下载链接仍在模型详情中。
- 修改规则后执行前端演示测试、后端导航测试与两种前端构建，确保所有实体均可到达且同一分支没有重复 ID。
