# 模型、工具与成本选型

产品目标是帮助用户选模型、工具和项目，比较成本方向。需求未确认前继续聊天澄清；确认后默认输出 180～350 字，最多三条适用路线。每条包含推荐组合、费用组成或有依据的估算、关键代价、官方链接。部署教程、完整架构和长篇报告留待用户明确追问。

例如“低成本 AI 写小说并做网站”，任务同时覆盖文本生成和网站开发：

- API 自建：查询文本模型及接口资料，并补网站托管候选。当前库能检索 DeepSeek、Cloudflare Workers 等；费用分为模型输入／输出、网站托管、数据库。
- 本地部署：查询开放权重文本模型与运行／界面项目。当前库能检索 Qwen3-8B、Open WebUI 等；费用涉及硬件、电费、维护，不能默认比 API 便宜。
- 现成平台：比较网页创作入口和建站产品。DeepSeek 网页版可试写；v0 可用于建站方向，但聊天会员、建站积分、托管与模型 API 的费用和交付能力须分别核对。

上述是可解释的候选方向，不是模型效果或最低价排名。价格、使用量与单位证据不足时列成本结构，不编造月费；用户必须要独立网站时，聊天网页不能冒充网站交付。

## 检索链路

1. 模型整理用户明确表达的六项条件，保留对应原文；可在同次调用中返回会话主题摘要。
2. 共享的 `recommendation-policy.json` 把整理后的目标映射为文本／代码、图片、声音、视频生成，以及文字、图片、声音、视频理解等能力。
3. 沿分类树向上查找祖先分类，匹配后台同一套已发布事实。按允许路线选择模型、运行项目、平台与必要的托管工具；默认最多 12 条、每实体最多两条。
4. 拒绝的路线和离线要求会过滤候选。明确指定的不合适型号仅作为 `reference` 返回，供解释限制，不作为路线推荐。例如用视频模型写小说时，要指出任务不匹配。
5. 提示中传入 `SELECTION_CONTEXT` 和实际证据。联网开启时继续组合网页检索，库内 `[K]` 与网页 `[W]` 分别追溯；后续续写保持已有证据。

目前是基于需求摘要、能力规则、分类和发布事实的检索，不声称已实现向量语义检索或效果评测。复杂隐喻、模糊需求仍可能需要用户进一步澄清。

`public-datasets.json` 注册全部公开资料。新增 `advisor-tools-2026-11-07.json` 的五个工具／产品独立于上一轮 166 项审查快照，保留旧审查清单的原始范围及指纹。

## 标题与删除

新建默认会话使用 `title_mode=auto`。需求整理模型会同时给出简短主题，在成功保存消息时更新标题；缺少有效主题时使用目标摘要作为后备，不增加独立模型请求。手动改名后设置为 `manual`，即使手动名字恰为“新对话”也保持锁定。并发生成不能覆盖手动改名。来源不明的历史自定义标题保守保留。

删除按钮先打开原生确认对话框，展示会话名；取消或 Escape 不删除，确认才发出删除请求。保留原来的软删除和撤销行为。

本地后端更新时，先同步 main 并在后端虚拟环境执行：

```bash
python -m alembic upgrade head
python -m app.curated --dataset advisor-tools-2026-11-07.json --apply
```

导入默认可省略 `--apply` 预览。旧事实冲突仍进入审核，不覆盖历史版本。Pages 自动加载注册的公开资料；浏览器中的会话、模型设置和搜索设置保留。
